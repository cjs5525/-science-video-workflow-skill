# 第1—2步：研究、口播与视听策划

## 第1步：核心问题与证据

从用户的问题或原始灵感发散，再收束为观众能跟上的因果链。原始灵感保留，只更新派生索引；不为了固定片长堆百科或硬删必要解释。

开头直接提出本期核心问题。记录观众已知、疑问、常见误解、机制和片末能理解的内容，同时提出适合图解的关系或过程。

核查关键主张时优先原始研究、官方数据和专业机构材料；当前新闻、数字、规则和软件能力应重新检索。旧聊天只提供线索，不能作为科学证据。

每项关键主张登记：

| 字段 | 要求 |
|---|---|
| 主张ID与采用位置 | 能追到脚本/图解 |
| 来源 | 真实标题、作者/机构、URL、发表日期及本次核对日期 |
| 数据口径 | 数据对应时间、对象/地域范围、单位、统计方法 |
| 性质 | 预测、模型、假设或实测；示意与事实区分 |
| 结论与边界 | 支持的具体说法、限制、矛盾来源与待核项 |

不同口径的数字不直接排名。日期异常、未来“实测”或相互矛盾时先查明，证据不足则收窄措辞或标待核。类比帮助理解，不承担科学证明。

交付 `选题与结构-vN.md`、`资料核查-vN.md`。主题已明确就推进；只有会改变解释范围的关键选择才询问。

## 第2步：自然问答与录制稿

读取用户已有且允许使用的口播风格文件。缺少时采用平实聊天语气，不编造个人经历、口头禅或用户偏好。公共技能不附带原作者私人声线样例。

- 主持人顺着问题解释；小云承担确实需要的追问、复述或转折，不为每段凑发言。保留自然反应、具体动词与顺口连接词，避免讲课式收束、刻意金句和满篇语气词。
- 本流程的新录制稿避用“不能把……当成……”及同义训诫句；改用具体事实和适用条件说明。科学区别和必要条件仍需讲清，重复核查声明移到制作说明。
- 陌生概念首次出现先补最小背景，再给术语。每句能自然接上上一句，必要总结直接回答眼前问题。
- 可朗读台词、表演提示、制作提示分别存放。纯TTS文本不得含角色名、工程ID、括号动作和情绪提示；情绪通过服务支持的独立参数传递。
- 章节用P0…Pn，主持台词用YS编号，第二声音用XY编号，解释图解用R编号。编号只用于工程，章节黑幕只显示主题。
- 分镜按稳定ID绑定：画面任务、重点信息、素材类型、进出方式、预计时段、来源/工具、验收点。录制前秒数标预估。
- 同步规划互斥的实拍类别R与解释动效类别D，保留关键面对面表达。角色动画不属于计划产物；第二声音由实拍、图解或自然反应镜头承接。

先查事实/因果/口径，再查口语/问题递进/视听节奏。用户逐句改稿先落实具体修改，再通篇检查同类表达；只有得到授权才更新其长期风格文件，不能改旧稿冒充原话。

交付 `口播稿-vN.md`、适用时的 `小云台词-vN.md`、`分镜与动效规划-vN.md`。将具体录制稿作为待确认候选；风格认可不等于录制稿定稿。确认后同步纯TTS文本与分镜版本；修改已确认脚本时检查原片、配音及下游依赖。
